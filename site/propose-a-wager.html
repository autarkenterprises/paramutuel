Propose a Wager

This page is for facilitated wager creation: common templates for enumerated and freeform pools, a streamlined subset of options, and (once live) assisted signing. The full self-custody app already supports choosing deployment, bitmask payoff policy, and factory parameters.

Assisted wallet experience (in development)

The protocol stays collateral-agnostic and unchanged on-chain. Per ADR-0006, the public site may offer assisted transaction UX (sponsorship, permits, policy rails) while the dApp stays fully self-custodial.

ADR-0007 defines an Assisted Transaction Gateway: signed intents, pluggable approval paths (EIP-2612, Permit2, sponsored approve), and optional paymaster-style adapters — so users should not need to reason about separate ETH-for-gas and USDC (or other ERC-20) steps for propose or bet once the pipeline is wired.

Roadmap detail: research/assisted-ux-roadmap.md.

Templates for common wagers

Enumerated templates pre-structure outcome labels and timing (classic or bitmask rules). A freeform template skips fixed outcomes: bettors supply text answers at stake time. The streamlined form (below) will apply defaults you can adjust before submit.

Yes / No

Single question with two labeled outcomes (e.g. “Will X happen by date D?”).

  • Proposition text
  • Yes label · No label
  • Betting close · Resolution window
  • Collateral (USDC-first happy path)

Streamlined creation

A short wizard will live here: choose a template, edit text and windows, confirm resolver (default: you), then submit via the assisted gateway when available (or fall back to the full app).

  1. Template — pick Yes/No, pick-one, or timed event.
  2. Details — proposition, outcomes, collateral, schedule.
  3. Review — fee recipients and advanced options only if needed.
  4. Submit — one comfortable signing path (assisted) or link out to the full dApp.

Form and gateway integration — under construction. Until then, use the full app for end-to-end factory deploys.

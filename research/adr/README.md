- `ADR-0018-collateral-curation-overlay.md`
  - **Implemented** by ADR-0020 (AAR initial; the ADR-0017 manifest item carries over). Implements ADR-0006's already-accepted collateral-curation decision (still "copy, not flow code" per its AAR) as an off-chain `config/collateral-allowlist.json` overlay consumed by the dApp / site / indexer, under the standing **"neutral core, safety as opt-in overlay"** principle. **No `src/` change**: the core stays collateral-agnostic and its solvency guarantee is documented as scoped to *standard* ERC-20; no-bool tokens (USDT-class) fail safe by revert, fee-on-transfer / rebasing tokens are pinned out-of-scope by regression tests. The universal-fallback path is preserved behind a warned opt-in so the protocol stays permissionless. Builds on ADR-0006 / ADR-0016 (Tier-1 / Tier-2) / ADR-0017 (manifest). Open questions for operator input on the curated token set per network and whether to later add the optional on-chain registry + curated-factory wrapper.

- `ADR-0022-indexer-vm-hosting.md`
  - **Implemented** (2026-11-08; AAR in the ADR, to be revisited after the first full month's bill). Moves the hosted indexer off Cloud Run, where the CPU was throttled between requests, the database lived in `/tmp` and up to three instances ran, onto an Always Free e2-micro VM. The resolution service runs on the operator's machine, so the resolver key stays off the cloud.
- `ADR-0023-collateral-receipt-check.md`
  - **Implemented in source** (2026-11-09; AAR in the ADR), live once the corrected factory is deployed. Every collateral pull (the three bet functions and the factory's seed pull) checks the wager's balance and reverts `CollateralShortfall()` when less arrived than was recorded. Fee-on-transfer tokens therefore fail safe instead of leaving the last to withdraw unpaid. It is neither balance-delta accounting nor an allowlist, the two options ADR-0018 rejected. An excess is accepted, and rebasing tokens remain unsupported. Implementation notes: `docs/ADR-0023-IMPLEMENTATION.md`.

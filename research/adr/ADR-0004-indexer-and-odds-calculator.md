# ADR-0004: Minimal Custom Indexer and Odds Calculator

- **Status:** Accepted
- **Date:** 2026-03-20

## Context

The project needs:

- service-agnostic wager scanning
- a lightweight explorer for wager states
- dApp/service odds and payout previews
- minimal dependencies with strong test coverage

## Decision

1. Build a **minimal custom indexer** first, not hosted subgraph.
2. Implement **odds/payout calculator** in dApp and service using indexed state + on-chain checks.
3. Keep indexer architecture simple and deterministic.

## Minimal Indexer Scope (v1)

Ingest and persist events:

- `WagerCreated`
- `BetPlaced`
- `Resolved`
- `Retracted`
- `Expired`
- `Claimed`
- `FeeAccrued`
- `FeeWithdrawn`

Derived fields:

- wager status: `Open | Resolved | Retracted`
- unresolved overdue boolean (`now > resolutionDeadline` and still open)
- per-outcome totals, total pot, fee bps, proposer, resolver

Operational requirements:

- reorg-safe ingestion
- deterministic replay from a configured start block
- idempotent event application

## Odds / Payout Calculator Requirements

For each wager/outcome:

1. **Current implied payout multiple if outcome wins now**
   - `multiple_i = netPot / outcomeTotal_i` (if `outcomeTotal_i > 0`)
   - where `netPot = totalPot - totalFees(totalPot)`

2. **Expected payout for user bet amount `x` on outcome `i`**
   - Pre-bet preview if wager resolved immediately after this bet:
   - `newPot = totalPot + x`
   - `newOutcomeTotal_i = outcomeTotal_i + x`
   - `previewPayout = x / newOutcomeTotal_i * netPot(newPot)`

3. **Post-bet odds impact preview**
   - Show before/after payout multiple and pool share for selected outcome.

4. **Edge-case handling**
   - no-liquidity outcomes
   - wagers no longer open
   - decimal precision and rounding disclosure

## Testing Requirements

- unit tests for formula correctness and rounding behavior
- fixture tests with multi-outcome wagers
- integration tests against testnet indexed data for consistency

## Consequences

### Positive

- independent visibility layer for dApp and service
- supports scanner, sweeper, and analytics
- enables bettor decision support via odds preview

### Tradeoffs

- custom infra maintenance burden
- must handle chain reorg and backfill logic carefully

## After Action Report

**AAR date:** 2026-05-06
**AAR status:** Backfilled 2026-05-06 per ADR-0012

**Outcome vs success criteria:**

- *Minimal custom indexer ingesting `WagerCreated`, `BetPlaced`, `Resolved`, `Retracted`, `Expired`, `Claimed`, `FeeAccrued`, `FeeWithdrawn`.* **Met** — `service/indexer/` ingests all of these (V3 events updated by ADR-0010). Hosted on Cloud Run (`docs/INDEXER-HOSTING.md`).
- *Derived fields: status, unresolved-overdue boolean, per-outcome totals, total pot, fee bps, proposer, resolver.* **Met** — explorer (`service/explorer/`) consumes derived fields from the indexer; dApp odds preview reuses them.
- *Reorg-safe ingestion, deterministic replay, idempotent application.* **Met** — `apply_log` is idempotent against V3 branches (per the 2026-05-06 commit `docs(upgrade-runbook): update apply_log note from v1/v2 to V3 branches`). Start-block / from-block configured per network in `config/deployments.json`.
- *Odds / payout calculator with implied multiple, expected payout for `x`, post-bet impact, edge-case handling.* **Met** — preview logic in `dapp/logic.js` and the explorer; aligned with `docs/PAYOUT-CALCULATION.md` worked examples.
- *Unit + fixture + integration tests.* **Met** — Foundry tests for contract math, Python tests in `service/indexer/` and `mcp_server/tests/`, integration via the testnet suites.

**Outcome vs failure criteria:**

- *Custom infra maintenance burden materializes.* **Triggered, mitigated** — Render free tier proved insufficient (`fix(indexer): bisect eth_getLogs ranges on RPC HTTP 400`, `fix(indexer): robust live sync start block, chunk size, and /health diagnostics`); Cloud Run replaced it within ~24h. Captured as `LESSONS.md` L-004.
- *Chain reorg / backfill mishandled.* **Avoided so far** — no production reorg incidents recorded. Caveat: Base Sepolia reorgs are rare; the discipline has not been stress-tested under a deep reorg.

**Lessons:** L-004 (hosted-service free-tier boundary) generated by this ADR's rollout.

**Follow-ups:**

- Reorg stress test against a controlled fork before mainnet; record outcome in this AAR via revision.
- Consider whether `protocol_version` reporting needs to surface the V3-only state more clearly to clients (currently implicit).

**Revision schedule:** at first deep-reorg event observed, or before mainnet deploy, whichever comes first.
